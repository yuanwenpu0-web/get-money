# 虚拟币指标系统性评估方案

> 适用对象：`backend/app/catalog_indicators/` 已注册的 **127 个指标**（Pine 移植，`registry.py` 按 SHA-256 钉住源码）、
> `backend/app/features/` 内的本地特征、以及后续新移植的指标。
> 定位：研究方案与执行手册，不是投资建议。所有结论必须由本文件规定的产物文件支撑。

## 0. 现状基线：已经有什么、缺什么

先承认家底，方案才有意义。当前仓库里已有一轮完整的一手结论：

`docs/signal-screen.md`（1h / 400 天 / 40 币 / 前瞻 24 根 / 往返成本 0.12%）：

| 项 | 数值 |
|---|---|
| 扫描布尔列 | 152 |
| 退化列（触发率 <0.2% 或 >60%） | 48 |
| 有效检验 | 132 |
| 净超额为正 | 64 |
| **通过三关（CI 下界>0、FDR q<0.10、分段同号≥3/4）** | **0** |

现成能力（直接复用，不要重写）：

| 能力 | 位置 | 状态 |
|---|---|---|
| 事件化信号筛选（上升沿 + 非重叠 + 毛/净 + bootstrap + BH-FDR + 分段同号） | `backend/scripts/signal_screen.py` | 可用 |
| 检测器自校准（正对照泄漏信号 / 负对照随机信号 / 半衰对照） | `backend/scripts/signal_screen_calibrate.py` | 可用 |
| 单币策略回测（含基线、随机方向基线、期望值 CI、purge_bars=horizon） | `backend/app/backtest/runner.py:498` | 可用 |
| 参数寻优（训练段选参 / 验证段判定 / 成交笔数门槛 ≥30 / 进程池） | `backend/app/backtest/optimizer.py` | 可用 |
| 显著性工具（bootstrap CI、IC、随机基线分布、百分位） | `backend/app/backtest/significance.py` | 可用 |
| 绩效指标（收益/回撤/Sharpe/盈亏比/期望值/费用） | `backend/app/backtest/metrics.py` | 可用 |

**三个决定性缺口**（本方案要补的核心）：

1. **方向单边**：`signal_screen.py:100` 的 `forward_return` 只算多头收益。看跌类信号（`strong_sell`、`bear_cross`）
   的真实优势应表现为"信号后下跌"，在现口径下永远算不出正 edge。→ 这就是 `strong_sell` 显示 +0.27% 毛收益
   却被判 inconclusive 的原因：它其实是"卖出后上涨"，方向没对齐。
2. **基准是 0 而不是市场**：`net = gross - ROUND_TRIP`（`signal_screen.py:223`）只扣成本、不扣同期无条件收益。
   在单边上涨的 400 天窗口里，任何多头信号都会显得"正"，64/132 为正有多少是 beta 贡献无法区分。
3. **只有池化结论，没有分层与组合**：40 币混在一起，看不出"这个指标只在 4h 主流币有效"；
   也完全没有相关性/冗余/组合脚本，而组合是最后唯一可能救回正 edge 的路径。

## 1. 五条设计铁律（违反任一条，结论作废）

1. **先证量具，再测标的。** 每轮换周期/换股票池/改成本，先跑正负对照。检测器抓不到泄漏信号，后面的 0 结果没有意义。
2. **edge = 超额，不是收益。** 事件收益必须减掉同池、同周期、同区间的无条件收益（去 beta），再减成本。
3. **一个事件一次计数。** 条件持续为真只算一次入场（上升沿），相邻事件间隔 ≥ 前瞻跨度，否则 n 虚高、p 值虚低。
4. **选择与判定必须分开。** 任何"挑出来的"东西（最佳周期、最佳币种组、最佳组合规则）都要在没参与挑选的样本上判定；
   切分处保留 purge ≥ 前瞻跨度。
5. **失败保留。** 不显著就写 `REJECTED`，不许改参数重跑到显著为止；重跑即计入试验次数，进 DSR/PBO。

## 2. 数据层

### 2.1 必需字段

| 表 / 来源 | 字段 | 用途 | 备注 |
|---|---|---|---|
| `klines` | `symbol, interval, open_time, open, high, low, close, volume, quote_volume, trades` | 指标计算、事件收益、流动性排序 | `(symbol, interval, open_time)` 已有唯一约束 |
| `funding_rates` | `symbol, funding_time, rate` | 永续持仓成本、拥挤度过滤 | 时间戳带 ±ms 偏移，聚合前必须 `dt.floor('8h')` |
| `sentiment` | `oi_value_usd` 等 6 列 | 情绪/杠杆横截面特征 | API 仅约 30 天 1h 历史 |
| `coin_metrics` | `metrics` JSON（成交额、排名、市值） | 流动性/市值分层 | 快照表，取事件时点最近一条，禁止用未来快照 |
| 派生 | 基准序列（BTC 或池等权收益） | 去 beta、相对强弱 | 需 `scripts/` 新增，一次算好落盘 |

**必须新增的两类数据**（否则第 4 节的分层与第 6 节的容量评估做不了）：

- **历史 universe 快照**：当前 `resolve_universe` 只返回"此刻仍在上市"的币，用它回测等于只留下幸存者。
  至少要落一份"每月成分 + 下架时间"清单，用于幸存者偏差披露或剔除下架币的双口径对照。
- **深度/价差代理**：没有盘口历史时，用 `quote_volume` 与 `trades` 推"单笔均额"，作为滑点分层的代理变量；
  分层滑点假设必须写进产物，不能全局用一个 0.02%。

### 2.2 数据质量门（不通过就不许进评估）

| 检查 | 判据 | 处理 |
|---|---|---|
| 步长一致性 | 相邻 `open_time` 差值恒等于周期 | 缺口不插值，直接标记并缩短样本 |
| 缺口率 | 单币缺口 bar / 应有 bar < 1%（15m 可放宽到 2%） | 超限剔除该币该周期 |
| 重复 bar | 唯一约束冲突数 = 0 | 存在则先去重再算 |
| OHLC 逻辑 | `low ≤ min(open,close) ≤ max(open,close) ≤ high` | 违反即丢弃该 bar 并计数 |
| 零成交 bar | 占比 < 5% | 超限视为流动性不足 |
| 极端插针 | `|ret| > 20×ATR` | **标记不删**（真实行情），但在敏感性分析里做"剔除后是否翻转" |
| 上市时长 | ≥ 评估窗口 + 指标最长回看 + 前瞻跨度 | 不足则该币不参与该周期 |
| 口径固定 | 同一轮内 derived（1m 聚合）与 native（直查 interval）**不得混用** | 结果里必须带 `source` 字段 |

已知硬约束（写进每份报告的限制段落，不许省略）：

- 1m 历史仅约 91 天 → 依赖 lower-tf intrabar delta 的指标（absorbption 类）只能在 15m 上做，且样本极短；
- 1h 多币种活跃从 2026-09 起才有 500+ 币覆盖 → 400 天窗口实际是"最近 400 天里有数据的币"，池化会前后期币种构成不同；
- `max_hold` 超过窗口时，末尾事件的前瞻收益必须置 NaN，不能前向填充。

## 4. 第 1 层：单指标信号准确性（事件研究）

### 4.1 事件定义（必须一次说清）

- **事件时刻** `t`：布尔条件由假转真的那根 bar 的**收盘**。信号在 `t` 收盘后可知，入场按 `t+1` 开盘或 `t` 收盘（二选一，全轮统一，写进产物）。
- **前瞻收益** `r_h(t) = close[t+h]/entry(t) - 1`，`h` 取一组而非一个：`{6, 12, 24, 48, 96}`（1h 上相当于 6h–4d）。
  单点 horizon 的选择本身就是一次隐性调参，必须给曲线。
- **去重**：上升沿 + 相邻事件间隔 ≥ `h`。
- **方向**（补第 0 节缺口 1）：

| 模式 | 定义 | 用途 |
|---|---|---|
| `long` | 只测买入后上涨 | 看涨指标 |
| `short` | 测卖出后下跌（`-r_h`） | 看跌指标 |
| `aligned` | 指标自报方向 × 收益方向 | **推荐默认**：`sign(column_direction) × r_h` |

实现建议：给指标列加一张**方向声明表**（`catalog_indicators` 侧或独立 `docs/indicator-directions.yaml`），
未声明的列按 `long` 处理并在结果里标 `direction_assumed=true`。方向靠猜是这套评估最容易死的地方。

### 4.2 超额口径（补缺口 2）

三种基准，逐层收紧：

| 模式 | 基准 | 回答的问题 |
|---|---|---|
| `zero` | 0 | 绝对收益（现口径，仅作对照） |
| `unconditional` | 同币同周期、同区间的**事件期望**（全 bar 前瞻收益均值） | 该指标是否优于"随时买入" |
| `cross_section` | 同一时刻全池平均前瞻收益 | 该指标是否优于"同时买一篮子" |

**判定只用 `cross_section` 或 `unconditional`**；`zero` 只用于复现历史结论。
净超额 `excess = r_h - benchmark_h - cost`。

### 4.3 四道关（全部通过才算 candidate）

| 关卡 | 判据 | 理由 |
|---|---|---|
| 1 效应 | `mean(excess) > 0` 且 bootstrap 95% CI 下界 > 0（≥2000 次，按**币**做 block bootstrap） | 区分"亏损"与"不知道" |
| 2 显著性 | FDR q < 0.10；同时报告 **Westfall–Young max-T** 置换 p 值 | 152 列高度相关，BH 的独立性假设不成立 |
| 3 稳定性 | 时间 4 段 ≥3 段同号；滚动 90 天窗口 IR 符号一致率 ≥ 70% | 排除单段行情 |
| 4 可执行 | 事件频率 ≥ 30 笔/轮，且单笔净额 > 2×单笔成本；`excess` 在 2× 成本下仍 > 0 | 排除成本幻觉 |

**已知锚点**（用来自检判定器是否退化）：`capital41_duo.rsi_turn_up` 1532 事件、净 +0.4624%、CI 下界 +0.1028，
但 q=0.180 → 必须落在 `likely_noise`。若你的新版本把它报成 candidate，先怀疑判据被放松了。

### 4.4 交易化前的必要一步

事件研究只能说"信号后价格怎么走"，不等于"能赚钱"。任何 candidate 必须再走一遍 `runner.run_backtest`
（真实仓位、分批止盈、止损、资金占用），两者结论不一致时以回测为准，并在报告里写明差异原因。

## 5. 第 2 层：币种/周期适配范围（横截面）

### 5.1 四个分层维度

| 维度 | 切法 | 目的 |
|---|---|---|
| 币种 | 单币独立统计 + 按主流/山寨分组 | 是否存在"只对 BTC/ETH 有效" |
| 周期 | 15m / 1h / 4h / 1d 各跑一轮 | 同一逻辑在不同噪声水平下的存活 |
| 流动性 | 按 `quote_volume` 分位分 4 档（Q1–Q4） | 决定容量与滑点假设 |
| 波动率 | 按滚动 ATR% 分位分 4 档 | 趋势类指标通常依赖波动率区间 |

分组用**事件时点**的属性，不是评估末期的属性（用末期分层 = 未来信息）。

### 5.2 正确的做法：先检验交互，再看格子

朴素做法是"32 个格子各自跑一遍，挑最好的报告"，这是标准的二次选择偏差。正确顺序：

1. **整体交互检验**：`excess ~ indicator + group + indicator×group`（或对事件做混合效应 / 分层 bootstrap），
   先回答"分组是否显著改变效应"。不显著 → 只报池化结论，不报任何分组"亮点"。
2. **收缩估计**：每个格子的均值向池化均值收缩 `w = n/(n+k)`，`k≈30`。事件数 <30 的格子只报样本量，不报结论。
3. **单调性检验**：若流动性/波动率真的在起作用，效应应随分位**单调**变化。非单调的"Q3 最好"基本是噪声。
4. **留一币检验**：逐币剔除重跑，结论不得依赖单币（单币贡献 >30% 即标记 `fragile`）。

### 5.3 通过标准（适配范围结论）

一个指标可以被判为"在某分组有效"，当且仅当：

- 该分组内事件数 ≥100（跨币池化）且覆盖 ≥5 个币；
- 分组内 excess CI 下界 > 0，且 q < 0.10（在**该分组内**的多重比较集合里校正）；
- 与池化结论方向一致（不允许"整体无效但某个子集有效"被当作正面结论，只能作为待复核线索）；
- 交互检验 p < 0.10（否则分组差异不能解释为真实异质性）。

### 5.4 组合层面的必要提示

分层结论会诱导"每个币配一套指标"。这等于把 127 指标 × 4 档 × N 币变成上万次检验。
**允许的做法**：先按层选"层内排名前 3"的指标进入下一轮，层间的选择过程必须记录在选择日志里，
并把层数计入 DSR 的有效试验数（第 7 节）。

## 6. 第 3 层：多指标组合可行性

### 6.1 相关性排查（先做，成本最低）

| 层次 | 度量 | 阈值 | 含义 |
|---|---|---|---|
| 触发共现 | 事件时刻的 Jaccard / φ 系数 | >0.6 视为同源 | 两个条件是同一件事 |
| 收益相关 | 事件收益序列的 Spearman ρ（按时间对齐，只在对齐日算） | \|ρ\|>0.5 视为冗余 | 提供同一份 alpha |
| 家族共线 | 按 `catalog_indicators` 的 collection 前缀（`capital41_*`、`rsi_*`）聚类 | 家族只留代表 | 移植同源代码必然高相关 |

产出：`docs/indicator-redundancy.json`（127×127 矩阵 + 聚类树 + 每簇代表），
并用**层次聚类在 ρ=0.5 处切**，簇数即"有效独立信号数"——这个数同时是 FDR 校正的合理分母。

### 6.2 组合规则筛选（从简到繁，逐级验证增量）

| 规则 | 定义 | 风险 |
|---|---|---|
| R1 单信号 | 基线 | — |
| R2 AND（全部满足） | 触发率相乘，频率骤降 | 常因样本 <30 直接不可判 |
| R3 OR（任一满足） | 频率上升，稀释效应 | 接近"随时在场" |
| R4 排序打分 | 各信号 z 分加总后取 Top-K | 需要横截面，适合多币 |
| R5 条件分层 | 信号 A 在 regime B 下才生效 | 组数爆炸，必须预登记 |

**增量判定**：`excess(R_new) - excess(R_base)` 的 block bootstrap CI 下界 > 0，且
**同时**报告频率变化（组合降频 80% 后 CI 变宽，"不显著"≠"没增益"）。
只用"收益更高"判组合是错的——收益提升伴随频率下降时，等价于换了个更小的样本。

### 6.3 过拟合控制（组合阶段是重灾区）

- **预登记**：组合规则、候选指标、窗口在跑之前写进 `docs/indicator-combo-plan-{id}.json`，跑完不许改。
- **嵌套验证**：外层 walk-forward（训练 12 个月 / 验证 3 个月，滚动），内层做组合选择；
  外层每折的验证结果拼成一条 OOS 曲线，只用这条曲线下结论。
- **多重比较记账**：把本轮总尝试次数（指标数 × 周期 × 分组 × 组合规则）写入产物，
  用 Deflated Sharpe / PBO 修正；尝试次数 <30 时 DSR 无意义，直接说"试验数不足，无法校正"。
- **随机基线**：用 `significance.random_baseline_distribution` 生成"同频率随机组合"的收益分布，
  组合结论必须落在 95 分位以外。
- **单点依赖**：组合收益的 30% 若来自单一币/单一时段，标 `fragile`，不进生产候选。

### 6.4 组合的通过标准

`PROMOTE` 需要同时成立：

1. OOS（外层拼接）Sharpe > 0 且 > 单信号 OOS 最大值；
2. OOS 最大回撤 ≤ 单信号最小回撤的 1.5 倍（组合不该更脆）；
3. 组合相对单信号的增量 CI 下界 > 0；
4. PBO < 0.5（若试验数够）；
5. 交易成本 2× 下仍为正。

任一不满足 → `REJECTED`，保留证据。

## 7. 评估指标字典（口径必须写死）

### 7.1 事件级（回答"信号有没有信息"）

| 指标 | 定义 | 陷阱 |
|---|---|---|
| 事件数 n | 去重后事件计数 | n 是"币·事件"，不是 bar 数 |
| 信号频率 | n / (币数 × 天数) | 太高无容量，太低无统计力 |
| 净期望 | `mean(r_h - benchmark - cost)` | 必须带 CI，不带 CI 的期望值不可引用 |
| 胜率 | `P(excess > 0)` | **单独看无意义**，必须与盈亏比同看 |
| 盈亏比 | 平均盈利 / 平均亏损 | 胜率 40% + 盈亏比 2.0 可以盈利，反之不然 |
| Profit Factor | 总盈利 / 总亏损 | 少量极端值主导，需同时给分位数 |
| MFE / MAE | 持仓期内最大有利/不利偏移（按 ATR 归一） | 决定止损与目标位是否可实现 |
| horizon 曲线 | 净期望随 h 的变化 | 峰值在 h=1 通常是成本残差，不是 alpha |

### 7.2 组合级（回答"能不能交易"）

| 指标 | 定义 | 说明 |
|---|---|---|
| 年化收益 / Sharpe | 按日频净值，365 天年化 | 与 `metrics.py` 口径一致，不另立标准 |
| 最大回撤 | 权益 / 滚动峰值 − 1 | 事件级无回撤，别在事件表里放 MaxDD |
| Calmar | 年化 / \|MaxDD\| | 加密货币高波动下比 Sharpe 更贴近体感 |
| 换手率 | 年换手次数 | 与成本线性相关，必须与净收益同报 |
| 资金利用率 | 在场 bar / 总 bar | 低利用率的高 Sharpe 无规模意义 |
| 容量 | 按分层滑点反推的可承载名义额 | 没有容量估计的结论不许上实盘 |

### 7.3 稳定性（最容易被忽略）

- 时间：4 段同号率、滚动 90 天 IR 符号一致率；
- 空间：逐币同号率（≥60% 币同号才算普适，而非"均值被两三个币拉起来"）；
- 参数：核心参数 ±20% 扰动后结论不变（参数悬崖 = 过拟合）；
- 成本：1×/2×/3× 成本下的净期望衰减曲线。

## 8. 成本与滑点

### 8.1 基本口径（与仓库现状一致）

```
单边成本 = fee + slippage
往返成本 = 2 × (fee + slippage)          # 现货默认 0.04% + 0.02% → 0.12%
净超额   = r_h - benchmark_h - 往返成本
```

### 8.2 必须做的四件事

1. **按流动性给滑点**，不要全局 0.02%：Q1（高成交额）0.01–0.02%，Q4（低成交额）0.10–0.30%。
   滑点假设写进产物，随分层结果一起报。
2. **成本占比归一化**：`cost_ratio = 往返成本 / (ATR% × 目标R)`。
   经验阈值：`cost_ratio > 0.3` 的策略在实盘几乎必死，事件研究阶段就该剔除。
3. **永续计资金费**：持仓跨 8h 结算点即计 `rate`（可正可负），1h 上平均持仓 24 根 ≈ 3 次结算，不可忽略。
4. **敏感性扫描**：1×/2×/3× 成本三档。结论在 2× 翻转 → 标 `cost_fragile`，不进候选。
   反例参照：`capital41_pdh_pdl.touch_week_low` 毛 0.284% → 净 0.164%，成本吃掉 42%，
   这类信号在 2× 成本下必然转负。

### 8.3 不许做的

- 不许用 maker 费率估算（事件研究假设立即成交，就是 taker）；
- 不许忽略滑点随下单量增长（容量评估里单独处理）；
- 不许把"成本前正、成本后负"写成"接近盈亏平衡，有优化空间"。那是负 edge。

## 11. 主要局限

1. **样本期单一**：1h 多币覆盖只有 2026-09 之后，跨不过一轮完整牛熊；任何"稳定"结论都只是短窗口内的稳定。
2. **1m 历史仅 91 天**：依赖 intrabar 结构的指标（delta、吸收、订单流代理）无法做长样本复核。
3. **无盘口历史**：滑点只能按成交额代理，真实冲击成本未知，容量结论是量级估计。
4. **幸存者偏差不可完全消除**：缺历史 universe 快照时，池化样本天然剔除了已下架币（通常是归零币），结论偏乐观。
5. **事件研究 ≠ 可交易**：不含资金占用、不含分批止盈、不含强平与资金费，必须由 S7 兜底。
6. **指标全部来自公开 Pine 脚本**：这类策略的公开性本身意味着已被大量交易者使用，剩余 alpha 有限；
   127 个指标不是 127 个独立假设，实际独立维度远低（见 S5 的簇数）。
7. **横截面去 beta 会掩盖择时价值**：若指标真实作用是"择时"（全市场同向），cross_section 基准会把它扣掉。
   所以要同时看 `unconditional` 与 `cross_section` 两种基准，结论不一致时如实说明。
8. **多重比较无法彻底解决**：DSR/PBO 只在试验数已知且预登记时有效；探索性研究天然记账不全。

## 12. 常见误区（按杀伤力排序）

| # | 误区 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 用 0 当基准，不减市场收益 | 牛市里所有多头信号都"有效" | 减同池同区间无条件收益 |
| 2 | 只测多头 | 看跌指标全部被误杀 | 方向对齐（4.1） |
| 3 | 逐 bar 计数 | n 虚高 10–100 倍，p 值虚低 | 上升沿 + 最小间隔 |
| 4 | 用胜率排序 | 高胜率低盈亏比的策略稳亏 | 胜率 × 盈亏比 × 频率一起看 |
| 5 | 挑最好的格子/周期/参数 | 二次选择偏差，OOS 崩 | 先交互检验，再收缩，选择计入试验数 |
| 6 | 组合 = 叠加过滤 | 频率掉到 10 笔，结论不可判 | 先算增量信息，再谈组合 |
| 7 | 忽略成本敏感性 | 2× 滑点即翻负 | 1×/2×/3× 三档必报 |
| 8 | 把"接近盈亏平衡"当机会 | 把负 edge 当成待优化项 | 净额为负即 REJECTED |
| 9 | 在同一段数据上反复调到显著 | p-hacking | 预登记 + 独立 OOS + 试验台账 |
| 10 | 指标内部用了未来数据 | 回测天堂，实盘归零 | 检查 `shift(-1)`、反向 rolling、`groupby` 后的 dtype 问题 |
| 11 | 混用 derived 与 native 口径 | 同一结论两种读数，无法比较 | 一轮内固定 source，产物带字段 |
| 12 | 用当前 universe 回测历史 | 幸存者偏差 | 历史成分快照，或明确披露 |
| 13 | 忽略资金费 | 永续持仓 3 天成本被低估 0.1–0.3% | 按结算点累加 |
| 14 | 单币贡献撑起结论 | 不可复制 | 逐币同号率 + 留一检验 |

## 13. 与现有代码的衔接（实施顺序建议）

按性价比排序，前三项都是小改动、高收益：

1. **改 `signal_screen.py`**：加 `--direction-mode {long,short,aligned}`、`--benchmark {zero,unconditional,cross_section}`、
   `--horizons 6,12,24,48,96`。改动局限在 `forward_return` 与 `verdict` 附近，约 80 行，
   之后重跑 1h/400d 即可得到"去 beta 后还剩几个"这一关键读数。
2. **加 `scripts/indicator_redundancy.py`**：复用 `signal_screen` 的事件提取，输出 127×127 相关与聚类。
   这是判断"127 个指标其实是几个"的唯一途径，成本一天。
3. **加 `--group-by`**：直接复用事件缓存，按 symbol / 流动性档 / 波动率档汇总，加交互检验（可用
   `scipy.stats` 或 bootstrap 分层抽样，不引入新依赖）。
4. 组合脚本与 walk-forward 最后做——只有 S3/S4 出了 candidate 才有意义。

**当前预期**：以 `docs/signal-screen.md` 的 0/132 为基线，去 beta 与方向对齐后大概率仍是 0–2 个 candidate。
若结果仍是 0，正确结论是"这批指标在现货 OHLCV 上没有可提取的 edge"，与项目 P0–P10 的历史结论一致，
而不是"再多扫几个指标"。**不要用扩大搜索空间来替代证伪。**
