# 收益率优化路线图（基于当前框架的渐进改造）

> 生成时间：2026-10-27；配套诊断：`docs/edge-diagnostic.md` / `.json`
> 定位：这是一份**带验收门槛的路线图**，不是收益承诺。每一阶段设一道 gate，
> 过不了 gate 就不许进入下一阶段——否则只会在噪声上继续堆复杂度。

---

## 0. 先说结论：现在的问题不是"参数没调好"

当前分层回测的收益是 **+0.051%/窗口**（5 窗口均值），单窗口胜率 2/5，
各档 test AUC 集中在 **0.40~0.63**（贴随机）。在这个量级上继续调参，
收益天花板约等于噪声宽度。所以本路线图的前两个阶段**不碰策略参数**，
只做一件事：把"有没有 edge"这件事变成可判定的。

### 本次诊断得到的五个事实

| # | 事实 | 数据 | 意味着什么 |
|---|---|---|---|
| 1 | **库里躺着 400 天历史，引擎只用 91 天** | BTC/ETH/DOGE 的 native 1h 有 9622 根（400.9 天，BTC 实测 9621 根零缺口），但 1m 只有 91 天，`_candle_query` 强制从 1m 聚合 | 浪费 **77%** 的可用历史 |
| 2 | **多币种历史极浅** | native 1h：≥300 天仅 **10 币**，120–300 天 **42 币**，<60 天 **463 币**；1m：**没有任何币种超过 120 天**，455/525 不足 60 天 | "多币种横截面"目前根本做不了，只能先做主流币 |
| 3 | **成本不是主要矛盾** | 成本吸收率（费用/毛收益）仅 **0.08~0.22**；往返成本 0.12% | 别急着搞 maker 返佣/降费，那是次要项 |
| 4 | **单窗口成交样本太少** | 60 天窗口、测试段 347 根 K 线 → 仅 **5~10 笔**成交，曝光率 19.9~35.7%，平均持仓 8.8~13.9 根 | 任何"收益 X%"都是几笔交易撑起来的，统计上不可推断 |
| 5 | **信号被过滤掉九成** | 主要拦截：`trend_conflict`×58~133、`below_threshold`×71~93、`weak_trend`×44~89、`model_edge`×42~53 | 开仓 bar 只有 14~65，成交 5~10 笔；要么放宽、要么承认就是低频策略 |

**一句话：** 现在的框架已经把"工程正确性"做完了（反前视、分档、对照组、证伪基线都在），
缺的是**信息量**——数据不够、特征太薄、标签丢掉了幅度。路线图就围绕这三点。

## 1. 阶段总览与 gate

| 阶段 | 主题 | 预期产出 | 通过 gate 的硬指标 |
|---|---|---|---|
| **P0** | 释放已躺着的 400 天历史 | 训练样本 4~9× | 主流币可用 1h 行数 ≥ 8000，walk-forward 窗口数 ≥ 6 |
| **P1** | 让"有没有 edge"可判定 | 证伪基建 | 每笔期望的 bootstrap 95% CI 能算出来；随机基线差值有明确正负 |
| **P2** | 标签改造（成本感知 + 幅度） | 模型目标函数换掉 | 样本外 IC > 0.02 且方向稳定，或 AUC > 0.55 跨窗口一致 |
| **P3** | 特征扩展（量价结构 + 横截面） | 特征 26 → 60+ | 单因子 IC 显著性检验通过 ≥ 5 个新特征 |
| **P4** | 横截面 pooled 建模 | 每档模型 → 全池模型 | 横截面 IC 均值 > 0.03，且分档不再优于统一（说明档位信息已被特征吸收） |
| **P5** | 成本与执行 | 净收益抬升 | 净/毛比 > 0.85，换手下降不伴随收益下降 |
| **P6** | 组合层与上线纪律 | 可实盘的资金曲线 | 组合 Sharpe > 1 且跨 6 个不重叠窗口为正 |

## 2. P0：先把已躺着的 400 天用起来（最高性价比，零策略风险）

### 2.1 为什么排第一

`backend/app/market/data_service.py::_candle_query` 的文档字符串里写着
"Legacy independently downloaded interval rows are deliberately ignored"——
所有非 1m 周期都被强制从 1m 聚合，且要求桶内分钟全部齐全。

后果是荒谬的：**SOLUSDT 库里有 9622 根 1h（400 天），但 1m 只有 7.2 天，
实际回测只能取到 7 天**。BTC/ETH/DOGE 同理，400 天缩水成 91 天。

### 2.2 怎么做

1. **给 `_candle_query` 加"聚合优先 + native 回落"**
   - 优先用 1m 聚合桶（口径不变，保证与历史回测可比）；
   - 某时间区间 1m 缺失、但 native 该 interval 行存在时，用 native 行补齐；
   - 关键：返回时打上 `source` 标记（`aggregated` / `native`），
     让上层能感知口径混合，不悄悄改变现有行为。
2. **一致性校验**：对 1m 与 native 1h 重叠的 91 天，逐根比对
   open/high/low/close，差异必须 < 1e-8；不一致则该桶仍走聚合。
   这一步不做就不能上线——两种口径混着训模型会引入假信号。
3. **扩展回填**：`backend/scripts/backfill_1h_history.py` 已有能力把 1h 补到
   `--days`（默认 120）。把它从 120 天提到 **400 天**，先覆盖那 10 个
   已有长历史的币 + 42 个 120–300 天的币，让它们都拉齐到 400 天。

### 2.3 Gate

- 主流币（≥10 个）可用 1h 行数 ≥ 8000；
- 45 天 walk-forward 能切出 ≥ 6 个**不重叠**窗口（现在只有 2 个有效段）；
- 重叠区间口径比对零差异。

> 这一步不做，后面所有阶段的样本量都是空的。

## 3. P1：让"有没有 edge"变成可判定的

现在最大的问题不是收益低，是**不知道收益是不是零**。5 笔成交跑出 +2.75%，
和 0 没有统计区别。本阶段不改策略，只加测量。

### 3.1 必做的三个测量

| 测量 | 怎么算 | 判定 |
|---|---|---|
| **每笔期望的 bootstrap 置信区间** | 对 trades 的 `return_pct` 做 1000 次有放回重采样 | CI 下界 > 0 才算"有 edge"；跨 0 就是没结论 |
| **IC（信息系数）** | 模型 `prob_up` 与 `future_return` 的 Spearman 相关，按窗口计算 | 均值 > 0.02 在 crypto 1h 才算可用；贴 0 说明模型是噪声 |
| **随机方向基线常态化** | 已有 `execution.randomize_directions`，但只在单币回测里跑过 | 每个窗口都要跑，且要跑**多个种子**取分布，不能只看一个种子 |

### 3.2 顺带修掉的两个测量陷阱

- **窗口重叠**：45 天窗口步长 15 天，5 个窗口其实只有约 2 个独立时间段。
  改成**不重叠窗口**，宁可少几个，也不要制造"样本更多"的错觉。
- **`minimum_sample_trades` 门槛太低**：`runner.py` 里是 `max(10, bars//50)`，
  10 笔就能参与选参。在单笔方差这么大的情况下，10 笔选出来的"最优参数"
  几乎必然是过拟合。建议提到 **30 笔**，选不上就老实保留当前参数。

### 3.3 Gate

- 每个回测报告自动输出期望的 bootstrap CI 和 IC；
- 至少 3 个不重叠窗口的结果放在一起能形成一致结论（同号）。

> **如果 P1 做完发现 edge 的 CI 跨 0，正确动作是停下来换数据源或换频率，
> 而不是继续往下做 P2~P5。**

## 4. P2：标签改造——现在的目标函数丢掉了最重要的一半信息

### 4.1 问题

`features/indicators.py` 里：

```python
data["future_return"] = close.pct_change(horizon).shift(-horizon)
data["label"] = (data["future_return"] > 0).astype(int)
```

标签是**纯方向二分类**，horizon 默认 5。这有三个致命问题：

1. **丢掉幅度**：涨 0.01% 和涨 3% 被当成同一个正样本，
   而前者扣完成本是亏的；
2. **无视路径**：中途先跌 2% 再涨回来，会被标成正样本，
   但实盘早在 -2% 被止损扫掉了；
3. **与成本脱钩**：成本 0.12% 往返，标签却不知道这件事。

### 4.2 改法（按优先级）

**第一优先：三分类 / triple-barrier 标签**

以入场后 `sl_pct`、`tp_pct`、时间上限三道边界先被触及者为标签：

- 先碰止盈 → `+1`
- 先碰止损 → `-1`
- 到期都没碰 → `0`（视作不交易，或按小额负样本）

这个标签直接对齐"实盘会发生什么"，且天然包含路径信息。
实现上复用 `trading/risk.py::stop_exit` 的判定语义即可，不用新写。

**第二优先：成本感知的二分类**

`label = future_return > cost_threshold`，其中
`cost_threshold = 2 * (fee + slippage) * 安全系数`。
至少让模型学会"不值得做的波动别做"。

**第三优先：样本加权**

按 `|future_return|` 加权，让高幅度样本在损失里占更大比重。
这一条改动最小，可以作为 P2 的先行验证——半天就能出结果。

### 4.3 Gate

- 样本外 IC 均值 > 0.02，且 ≥ 3 个不重叠窗口同号；
- 或 AUC 从 0.40~0.63 稳定提升到 > 0.55。

## 5. P3：特征扩展——26 个特征里没有一条"量价结构"

这是本路线图里**最有可能带来真实 alpha** 的一步。

### 5.1 现有 26 个特征的成分

`ret_1/3/5/10`、`rsi_14/7`、`macd` 三件套、`atr_pct`、`supertrend` 两件套、
`ema_ratio` 两件套、`bb_width/pos`、`volume_z`、`range_pct`、`close_pos`、
`adx_14`、`di_diff`、时间编码 `hour/dow` sin-cos、funding 若干。

一句话概括：**全是单币种时序技术指标**。缺三类东西：

### 5.2 该补什么

**① 量价关系（当前只有 `volume_z` 一个孤立特征）**

量价配合是判断突破真伪的核心验证层，现在完全缺失：

- 量价背离：价格创新高但量能未创新高（及其反向）；
- 放量突破 / 缩量回踩：突破时 `volume_z` 与 `range_pct` 的联合条件；
- 量能趋势：`volume` 短均/长均比值（现在是 50 窗 z-score，只有位置没有趋势）；
- 换手代理：`quote_volume` 的 z-score（比 `volume` 更可比，跨币种尺度一致）。

**② 价格结构（形态层面完全空白）**

- 摆动高低点（swing high/low）位置与距离：这是所有形态识别的底座；
- 距最近 N 根高低点的分位：`(close - low_N) / (high_N - low_N)`；
- 突破幅度：突破 N 根高点时的超出比例与回踩深度；
- 波动率状态切换：`atr_pct` 的短/长比值（波动率收敛往往先于方向选择）。

**③ 横截面相对强弱（crypto 最强的 alpha 源之一，现在一条都没有）**

每个时点上，把同一截面内所有币种的特征做 rank / z-score：

- `ret_1` 的截面排名（相对强弱，而非绝对收益）；
- `volume_z` 的截面排名（谁在异常放量）；
- 与 BTC 的相对表现：单个币的 beta 与残差收益（先剔除市场因子）。

**注意**：横截面特征依赖"同一时刻有多个币种的有效数据"。
按诊断事实 2，目前 1m 只有 70 个币够 60 天，455 个不足 60 天——
**所以 P3 必须在 P0 的 1h 历史补齐之后做**，先在那 10 个 400 天币种 +
42 个 120–300 天币种上验证，跑通了再扩池。

### 5.3 防线：防过拟合

特征从 26 扩到 60+，样本量不变成倍增加，必然过拟合。配套要求：

- 每个新特征单独算 IC，只有 **IC 显著不为 0（且跨窗口同号）** 才保留；
- 用 LightGBM 的 `feature_importance` 做后置筛选，删掉长期垫底的；
- 每加一批特征，必须重跑 P1 的证伪流程，不能只看收益变好。

### 5.4 Gate

- ≥ 5 个新特征通过单因子 IC 显著性检验且跨窗口同号；
- 加入新特征后，样本外 IC 相对 P2 有提升，而非只在 train 上变好。

## 6. P4：建模方式改造——从"每档一个 pooled"到"横截面 pooled"

### 6.1 现在的问题

`tier_model.py` 是"每档一个 pooled 模型"，pooled 的方式是**把多个币种的
时序样本按时间纵向拼起来**。样本量：单档 600~7320 行——对 LightGBM 来说
这点数据学不出稳定模式（这正解释了 AUC 0.40~0.63）。

### 6.2 改法

1. **截面标准化**：每个时间戳内做 rank 变换，再喂给模型。
   这样模型学的是"此刻谁强"，而不是绝对数值，跨币种可比、跨时间稳定；
2. **全池单模型 + tier 作为特征**：把规模/波动率档位编码成类别特征，
   而不是切成 8 个模型。样本量从"单档几千行"变成"几十万行"；
3. **验证假设**：如果全池模型 + tier 特征的表现 ≥ 分档模型，
   说明档位信息已经被特征吸收，分档架构可以退场（代码会大幅简化）。

> 记忆里那条"不要半吊子改造"（统一模型 + 分档参数反而最差）在这里是重要提示：
> 模型与参数必须配套，这次改造要**整套换**，不能只换一半。

### 6.3 Gate

- 横截面 IC 均值 > 0.03；
- 全池模型在 ≥ 4/6 不重叠窗口上不劣于现行分档模型。

## 7. P5：成本与执行——排在第五，因为诊断说它不是主要矛盾

成本吸收率只有 0.08~0.22，所以这里的目标是"别浪费"，不是"救命"。

| 项目 | 现状 | 可做的 |
|---|---|---|
| 费率 | fee 0.04% + slippage 0.02%（taker 口径） | 已有 `validation-1h-maker.md` 验证过 maker 口径；挂单成交可显著降本，但要接受成交率下降 |
| 换手 | cooldown 8~14 根，min_hold 未分级 | 按"预期 edge / 成本比"动态门控：edge 不足 2× 成本就不开仓 |
| 止损 | 固定 ATR 倍数 | 可试 ATR 状态自适应（波动率收敛期收窄） |
| 曝光 | 仅 19.9~35.7%，资金大量闲置 | 单币 sequential 模型天然限制曝光；若 P4 跑通，可考虑多币并行持仓 |

**注意顺序**：这些都要在 P2/P3 把 edge 做实之后才有意义。
在没有 edge 的系统上优化成本，只会让亏损变慢一点。

## 8. P6：组合层与上线纪律

- 组合层：现在 `backtest/portfolio.py` 已支持再平衡与加权。
  待 P4 有稳定 edge 后，加**相关性约束**（同向高相关币种限仓），
  这是控制回撤最直接的手段；
- `weighting.py` 的动态权重目前默认关闭（`weight_mode=equal`）。
  在 edge 未证实前不要打开——它引入的是另一层估计误差；
- 上线纪律：任何参数改动都要走"不重叠窗口 + 证伪基线 + bootstrap CI"
  三件套，且**写回模拟盘前必须先在报告里跑出同号结论**。

---

## 9. 明确不要做的事

基于已有的踩坑记录，以下几条建议直接放弃：

1. **不要继续调 tier 参数网格**。坐标下降已经在 18 组/轮上跑过，
   参数单调性是可信的，但收益增益不成立——瓶颈不在参数。
2. **不要做"统一模型 + 分档参数"这类半吊子组合**。已验证是最差分支（-0.027%）。
3. **不要用重叠窗口堆样本数**。5 个重叠窗口 ≠ 5 个独立样本，
   只会制造统计效力充足的错觉。
4. **不要在 1m 数据上做多币种横截面**。455/525 币种 1m 不足 60 天，
   做出来的是噪声矩阵。
5. **不要在 edge 未证实前动成本/仓位**。那是给零做优化。

## 10. 建议的执行顺序（含工作量量级）

```
P0 释放 400 天历史          ← 1~2 天，零策略风险，立刻做
 └─ gate: 主流币 ≥8000 行、≥6 个不重叠窗口
P1 证伪基建                 ← 2~3 天，只加测量不改策略
 └─ gate: bootstrap CI + IC 可判定
    ⚠ 若 CI 跨 0 → 停下来换数据源/频率，别往下走
P2 标签改造                 ← 3~5 天（样本加权可先行验证，半天）
 └─ gate: IC > 0.02 或 AUC > 0.55
P3 特征扩展（量价结构+横截面）← 1~2 周，最可能出真 alpha
 └─ gate: ≥5 个新特征 IC 显著且跨窗口同号
P4 横截面 pooled 建模        ← 1 周
 └─ gate: 截面 IC > 0.03
P5 成本与执行                ← 3~5 天
P6 组合层与上线              ← 持续
```

## 12. 合规与边界

- 本路线图只涉及研究方法与工程改造，不构成盈利预期或投资建议。
- 所有结论均基于本地已存历史，历史统计不代表未来走势。
- 任何阶段的 gate 未通过，正确动作是停止而非继续叠加复杂度。
- 技术信号仅为概率性描述，历史形态统计参考，不代表未来走势，不构成投资建议。
