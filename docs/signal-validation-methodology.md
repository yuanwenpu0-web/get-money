# 指标信号验证方法论：怎么判断「条件满足后是否真有盈利」

> 场景：库里有 36 个已移植指标，产出约 150 个布尔条件（`buy_signal`、`bull_sweep`、
> `vwd_cross_up`……）。想知道哪些条件满足后能赚钱。
>
> 本文给出一套可复现的判定流程，并在本库真实数据上跑完，结论见第 5 节。
> 工具：`backend/scripts/signal_screen.py`（筛选）、`signal_screen_calibrate.py`（自校准）、
> `backend/tests/test_signal_screen.py`（口径测试）。

---

## 1. 为什么「直接比收益率」一定会骗你

最直觉的做法是：把条件为真的那些 bar 挑出来，算它们之后 N 根的收益，跟全体平均比。
这个做法在本库数据上会稳定地给出**假阳性**，原因有四个，每一个都足以单独毁掉结论。

### 1.1 重叠计数：同一段行情被算了几百次

`bullish_lines_four_state.is_bearish` 实测触发率 **100.0%**。逐 bar 取样意味着
9601 根 K 线贡献 9601 个「样本」，但它们共享同一段未来收益，彼此高度相关。

后果：样本数 n 虚高 2 个数量级 → 标准误被低估 → t 值虚高 → p 值假性极小。
一个纯噪声信号也能跑出 p < 1e-20。

**正确做法**：取**上升沿**（条件从假变真的那一根）作为事件时刻，并要求相邻事件
间隔 ≥ 前瞻跨度，保证每个事件的前瞻窗口互不重叠。

### 1.2 退化列：有些「指标」根本不是条件

实测 152 个布尔列中 **48 个是退化的**：

| 列 | 触发率 | 问题 |
|---|---:|---|
| `bullish_lines_four_state.is_bearish` | 100.0% | 恒真，等于「一直持仓」 |
| `volatility_adjusted_momentum.oversold` | 99.4% | 近似恒真 |
| `capital41_regime_matrix.mean_reversion_state` | 97.5% | 近似恒真 |
| `bullish_lines_four_state.is_bullish` | 0.0% | 恒假，永不触发 |
| `capital41_confluence_core.long_signal` | 0.0% | 恒假 |

恒真列若参与排名，会因为它「覆盖全部行情」而拿到接近大盘的收益，看起来还不错，
实际零信息量；恒假列则直接污染分母。**必须在筛选前剔除**（本文用触发率 ∈ [0.2%, 60%]）。

### 1.3 多重比较：筛 150 个条件，纯运气也有几个 p<0.05

在 α=0.05 下，150 次独立检验期望产生 **7.5 个**假阳性。如果你按 p 值排序取前几名，
拿到的几乎必然是噪声。必须用 FDR（Benjamini-Hochberg）校正，看 **q 值**而不是 p 值。

### 1.4 成本：0.12% 的往返成本吃掉大部分「毛利」

本库现货口径：费率 0.04% + 滑点 0.02%，开平双边 = **0.12%**。
1h 上事件频率高的条件，毛利 0.3% 扣完成本只剩 0.18%，而波动就足以淹没它。
所以判定必须用**净超额**，毛利用来诊断「是不是被成本吃掉了」。

## 2. 判定流程（五步）

```
① 定义事件     条件上升沿 + 最小间隔 ≥ 前瞻跨度
② 定义标签     t 收盘 → t+H 收盘的收益（H 与持有期一致）
③ 算净超额     mean(未来收益) − 往返成本
④ 三关检验     CI下界>0  ∧  FDR q<0.10  ∧  时间分段同号≥3/4
⑤ 自校准       正对照必须显著、负对照必须不显著，否则不信 ④ 的任何结论
```

第 ⑤ 步最容易被跳过，但它决定前面所有数字是否可信。

### 三关为什么都要

| 关 | 挡住什么 | 单靠它会漏掉什么 |
|---|---|---|
| 净超额 CI 下界 > 0 | 「均值正但可能是运气」 | 筛 150 个必有几个偶然为正 |
| FDR q < 0.10 | 多重比较下的偶然 | 真实但微弱的 edge（会被过度惩罚） |
| 分段同号 ≥ 3/4 | 单段行情造出的假 edge | 样本太少的条件（分段无意义） |

三者是**与**关系。任一关不过就只能说「不知道」，不能说「有效」——
这个区分非常重要：`inconclusive` 不等于 `no_edge`。

## 3. 工具用法

```powershell
# 全量筛选（40 币 / 1h / 400 天 / 前瞻 24 根）
.\.venv\Scripts\python.exe backend/scripts/signal_screen.py `
    --interval 1h --days 400 --limit 40 --horizon 24

# 自校准：先证明量具是准的
.\.venv\Scripts\python.exe backend/scripts/signal_screen_calibrate.py

# 口径回归测试
.\.venv\Scripts\python.exe -m pytest backend/tests/test_signal_screen.py -q
```

输出 `docs/signal-screen.{md,json}`：summary、退化列清单、全部条件的
events / 毛利 / 净利 / 胜率 / t / q / CI / 分段一致性 / verdict。

换频率或换持有期时，`--horizon` 要跟着改（15m 建议 96 根 ≈ 1 天；4h 建议 6 根）。
**不要**用同一套 horizon 跨频率比较，那不是同一个问题。

## 4. 自校准结果（量具可信度）

| 对照 | 构造 | 均值净超额 | CI下界>0 币数 | 最小 q |
|---|---|---:|---:|---:|
| 正对照 | 直接偷看未来方向 | **+0.789%** | **12/12** | 6e-42 |
| 负对照 | 同触发率的随机布尔 | −0.172% | 0/12 | 0.327 |
| 半衰 | 正对照但前瞻砍半 | +0.200% | 1/12 | 0.418 |

读法：
- **正对照 12/12 显著**（t≈10，p≈1e-29）→ 检测链路（事件抽取 → 前瞻收益 → 检验）是通的。
  一个永远输出「不显著」的坏工具在这里也会输出「不显著」，正对照就是为了排除这种情况。
- **负对照 0/12 显著** → 判据没有假阳性泛滥。
- **半衰对照掉到 1/12** 说明一个额外事实：H=12 根（12 小时）的持有期在本库 1h 数据上
  连「偷看答案」都难以覆盖成本。这本身就是一条关于频率/持有期的有用信息。

## 5. 本库实测结论

口径：40 币 / 1h / 400 天 / 前瞻 24 根 / 往返成本 0.12%。

- 扫描 **152** 个布尔列 → 剔除 **48** 个退化列 → 有效检验 **132** 个
- 净超额为正的 **64** 个（约一半，符合噪声预期）
- **通过三关的候选：0 个**
- 按独立条件去重后为 **103** 个（`capital41_duo` 与 `capital41_duo_oscillator`
  等 24 组输出完全相同的列，属于重复计数，FDR 校正时要注意）

### 排名最高的几个（都未过关）

| 指标 | 条件 | 事件 | 毛% | 净% | CI下界% | q | 判定 |
|---|---|---:|---:|---:|---:|---:|---|
| capital41_pdh_pdl | break_month_high | 345 | +1.000 | +0.880 | −0.554 | 0.489 | inconclusive |
| capital41_duo | both_overbought | 642 | +0.915 | +0.795 | −0.029 | 0.350 | inconclusive |
| capital41_duo_oscillator | rsi_turn_up | 1532 | +0.582 | +0.462 | +0.103 | 0.180 | likely_noise |

`rsi_turn_up` 的 CI 下界虽为正（+0.103%），但 q=0.18 —— 在 132 次检验下，
这个「显著」完全可由偶然产生，且分段一致性只有 3/4 边缘。**不能当 edge 用。**

### 统计显著的都指向同一个方向：负

独立去重后最小 q 的五个条件，净超额**全为负**：

| 指标 | 条件 | 净% | q | 前半段% | 后半段% | 同号 |
|---|---|---:|---:|---:|---:|---|
| storm_gauge | is_calm | −0.302 | 0.0005 | −0.638 | −0.069 | 是 |
| bitcoin_market_regime | is_range | −0.351 | 0.0005 | −0.639 | −0.370 | 是 |
| adaptive_cycle_detector | crossing_up | −0.326 | 0.0005 | −0.618 | −0.249 | 是 |
| capital41_adx_filter | adx_cross_down | −0.305 | 0.0046 | −0.608 | −0.249 | 是 |
| storm_gauge | storm_ends | −0.316 | 0.0072 | −0.856 | −0.021 | 是 |

这些是**可靠地亏钱**：统计显著、分段同号、前后半段都负。它们能显著为负而不是零，
说明这批指标里确实编码了方向信息 —— 只是**方向是反的**，或者它捕捉的是
「行情已经走完」而非「行情将要开始」。

> 这一条是本次筛选最有价值的信息：不是「指标全是噪声」，
> 而是「指标的边际信息为负」。有信息 ≠ 有 alpha，符号搞反就是稳定亏损。

## 6. 为什么又是 0 个（与 P0–P10 的自洽）

这个结论不是孤例，而是与本项目已有结论一致：

- P3 探针：量价结构 / 横截面强弱 IC 全部 ≈ 0（最大 0.020，OBV 为负）
- P4 频率探针：1m / 15m / 1h / 4h 全频率 |IC| < 0.05
- P0/P1/P10：native 回落放大样本后 5 窗均值仍为负

本次 150 个条件全部不过关，是同一事实的第三次独立确认：
**1h 现货 OHLCV 价格序列上不存在可榨取的方向性 alpha。**
这些 TradingView 指标本质是同一份价格的变换，不引入新信息源，
所以它们不可能打破 IC≈0 的天花板。

---

## 7. 下一步该做什么（按性价比排序）

1. **不要**继续加指标 / 调指标参数。已证明边际≈0，再筛 150 个也是 0。
2. **把显著为负的信号当过滤器用**（最容易落地）：
   `bitcoin_market_regime.is_range`、`storm_gauge.is_calm` 触发时**不开新仓**。
   这不创造 alpha，但能砍掉一部分稳定亏损的交易。改动成本极低，可先做 A/B。
3. **换信息源**（唯一可能出正 alpha 的路）：
   订单流（买卖压力、大单净流入）、资金费率期限结构、链上数据。
   P9 的 `oi_value_usd`（IC=−0.0746，84% 币同号）是**目前唯一过 gate 的**，
   等覆盖 ≥60 天后用 `tier_backtest.py --exclude-sentiment` 做受控 A/B。
4. **换持有期**：半衰对照显示 H=12 根连偷看答案都难覆盖成本，
   说明 24 根可能是下限。做持有期敏感性（12/24/48/96）看净超额曲线。
5. 任何新特征投入前，先跑探针验证 |IC| > 0.02 —— 这是本库既定纪律。
